Ok here is the fix that should work, but try on the 56 because 56 has a known login and password first, and you can try up to 59.
56 login should be user: root and psswd: jci
You will need to create a serial cable connection on the CMU and then can use any terminal emulator (I use win10 with putty). You can use putty to log all outputs from the CMU is is fun to look through but really gives you little clue why it reboots.
Because the unit will wait until a USB is inserted you can watch the logging from the terminal window but it gets annoying. You will want to run this command (these are from my troubshooting notes). 
This should stop the continuous logging and screen writes
** Fix Reboot 59.00.XXX & Below 
Login - root / jci
Disable Watchdog - echo 1 > /sys/class/gpio/Watchdog\ Disable/value
***
Create a file called checksum_results.txt file and add a "C1" in it. Then create a blank file jci-loopstin with no extension on the USB stick. 
** Cannot Update 
cd /mnt/data_persist/
touch checksum_result.txt
echo "C1" >> checksum_result.txt
Add blank file to USB called "jci-looptestin"
***
After that place the USB stick in and see if you can get the system to get past the reboots on updating. I have used this fix multiple times to fix units that get jacked up where I cannot get them update as the failsafe and update are two separate versions.
